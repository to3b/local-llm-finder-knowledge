What gpt-oss-20b is

gpt-oss-20b is OpenAI's open-weight, text-only reasoning model. It uses a mixture-of-experts architecture rather than activating all its parameters for every token.

The OpenAI model card lists about 20.9 billion total parameters and 3.6 billion active parameters per token. The active count describes which parameters participate in a forward pass. It does not mean only that many weights need to be stored.

That distinction matters when comparing it with a dense model such as Qwen3 8B. A lower active count can reduce some computation, but it is not a shortcut for predicting total RAM, VRAM or tokens per second.

Checkpoint size and MXFP4

The model card lists a checkpoint size of 12.8 GiB, approximately 13.7 decimal GB. Checkpoint size is separate from runtime memory.

The official Hugging Face page explains that the expert weights use MXFP4 quantization and that the model can run within 16 GB of memory in supported configurations. This is a publisher deployment claim, not a guarantee for every backend, context setting or 16 GB computer.

MXFP4 is not the same format as a GGUF Q4_K_M conversion. Do not assume any download with a “4-bit” label preserves the publisher's memory footprint or execution path. Check the exact artifact and your runtime's gpt-oss support.

The quantization guide explains why precision labels alone cannot settle a hardware comparison.

Practical memory planning

Treat 16 GB as a starting tier to investigate with a compatible runtime and modest context. Reserve space for cache and buffers, and remember that installed system or unified memory is also shared with the operating system.

A 12 GB GPU has less capacity than the published checkpoint size alone. This reference therefore does not promise full GPU residency on an RTX 3060 12 GB. Some runtimes can distribute work across CPU and GPU memory; actual speed and allocation need to be checked.

Local LLM Finder uses a general planning model for quantization and context. Its Q4/Q5 choices for this catalogue entry should not be read as certification that a matching native MXFP4 artifact exists or has the same requirements. Verify the available format before downloading or buying hardware.

Explore your hardware in the Finder, then confirm the proposed setup in the runtime you intend to use.

Context and reasoning effort

OpenAI documents a context window of up to 131,072 tokens. The local application's supported and configured context can be lower, and sufficient memory is a separate requirement.

The catalogue currently uses 64K for planning. A model's published ceiling is not a recommendation to reserve the maximum context for every conversation. Start with a smaller allocation, test your workload, and increase it when needed. See context length and memory.

The model supports low, medium and high reasoning effort. A higher setting can spend more tokens before delivering the answer. Compare time to a useful answer as well as visible generation speed.

Use a compatible chat format

OpenAI specifies the Harmony conversation format for gpt-oss. Use a runtime that applies the appropriate template and correctly handles reasoning and final-answer channels. Feeding it a generic chat template can produce misleading results even when the weights load.

Download through the official model page, follow the runtime's supported setup, and test ordinary chat and your intended task before integrating tools. Tool descriptions do not execute functions by themselves; your application supplies that integration.

Memory and speed guidance here is for planning. It is not an RTX 3060, Mac or CPU benchmark.
