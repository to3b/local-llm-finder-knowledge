A starting point for an 8 GB GPU

For a first local run, try Q4_K_M with a 4,096-token context. The official file is about 2.50 GB, leaving room on an 8 GB GPU for the conversation cache and working buffers. This is a planning recommendation; actual allocation depends on your app and offload settings.

This page covers Qwen/Qwen3-4B, the 4.0-billion-parameter checkpoint with thinking and non-thinking modes. The model card lists an Apache 2.0 licence.

Download size and working memory

The official GGUF files are approximately:

  • Q4_K_M: 2.50 GB.
  • Q5_K_M: 2.89 GB, about 0.39 GB more.
  • Q8_0: 4.28 GB.

These are rounded download sizes in decimal GB. They exclude the conversation cache and runtime buffers; GPU tools may display memory in GiB instead.

For one conversation with an FP16 cache, our calculation from the published configuration gives about 0.60 GB at 4,096 tokens or 1.21 GB at 8,192. It uses 36 layers, eight KV heads and 128 values per head, storing both keys and values at two bytes each. This is a cache estimate, not measured VRAM use. Cache quantization, batching and placement change the result.

Keep thinking mode consistent

The checkpoint can spend tokens thinking before answering. For a useful comparison, keep that mode unchanged between runs. Qwen recommends temperature 0.6, top-p 0.95 and top-k 20 for thinking mode; use its current chat template and sampling guidance in the model card.

The card lists 32,768 tokens natively and 131,072 with YaRN. Extended context needs runtime configuration and additional memory. The configuration's allocation limit is not a reason to start at maximum context.

When to move up

Compare the same task with Qwen3 8B if this checkpoint's answers miss details you need. On an RTX 4060, load at 4K first, check GPU memory, then change either precision or context. See Q4 vs Q5 for that tradeoff.
