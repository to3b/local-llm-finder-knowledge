What Qwen3 8B is

Qwen3-8B is a dense, text-generation model from Qwen. The official model card lists 8.2 billion parameters and both thinking and non-thinking modes in the same checkpoint. It is a useful candidate for local chat, writing and coding experiments when a larger model would stretch the memory budget.

This reference covers Qwen3-8B itself. Other Qwen3 sizes and later variants can have different requirements; check the full checkpoint name before downloading.

GGUF download sizes

The official Qwen GGUF file list gives these rounded download sizes:

  • Q4_K_M: 5.03 GB.
  • Q5_K_M: 5.85 GB.
  • Q8_0: 8.71 GB.

These are decimal GB on disk. Runtime memory also includes the context cache, computation buffers and other allocations. A 5.03 GB download is therefore not a promise that the model runs entirely within 5.03 GB of VRAM.

Q5_K_M adds about 0.82 GB of weights compared with this Q4_K_M build. On a tight budget, that extra space competes with context. See Q4 vs Q5 for a practical way to choose.

VRAM and RAM planning

As editorial planning guidance, an 8 GB GPU is a plausible starting point for a Q4_K_M build at a modest context. A 12 GB card provides more room for Q5_K_M, context and runtime buffers. Neither tier is a tested compatibility guarantee.

Start at 4K context, close applications that use GPU memory, and check actual allocation in your runtime. If the model loads but fails when a longer prompt arrives, reduce context before assuming the download is corrupt. A smaller quant or partial CPU offload can also help, with a performance trade-off that depends on the backend.

A Mac uses shared unified memory, and a CPU setup uses system RAM. Both need space for the operating system and other applications. Use the Finder's appropriate hardware mode instead of treating installed RAM as dedicated VRAM.

The RTX 3060 12 GB reference explains this capacity tier. Compare your own setup in the Finder.

Native context versus extended context

Qwen documents 32,768 tokens of native context and up to 131,072 with YaRN scaling. Extended context needs a runtime and configuration that implement the required scaling. Changing a context slider alone does not establish that the model will handle the longer input correctly.

Local LLM Finder currently carries a 64K planning limit for this catalogue entry. That setting is an estimate input; it does not replace Qwen's native limit or verify your runtime's extended-context support.

Budget for the whole conversation, including the response and thinking output. The context-length guide explains why increasing the limit can increase memory use while the download stays the same size.

Thinking mode and local setup

Qwen's model card describes a chat-template setting to enable or disable thinking, plus prompt switches in supported configurations. Confirm how your app exposes those controls. Reasoning output can consume tokens and time before the final answer appears.

Use a supported runtime and the correct Qwen3 chat template. Start with the publisher's generation guidance, then compare a few prompts from your own workload. Review generated code and factual claims.

The figures here support planning, not hardware benchmarking. Runtime version, cache format, offload and context settings can change the result.
